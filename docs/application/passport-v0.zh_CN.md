# AI Passport Prototype v0：开发与架构

## 目标与范围

让沫纯住进 AI Passport。Milestone A 建立角色比例、中文、按键与转场；当前增量增加每日喝水、植物成长及 Wi-Fi 校时，手机本地网页仅用于配网。后端、BLE 同步、对话与旅行照片仍未实现。

官方上游：https://github.com/FoloToy/ai-passport 。基线提交 `0b9e4c81ee4421c0bac39ca3561d65a8285acd4a`。保留 BSP 与分区表，应用启动不再进入硬件测试菜单。官方示例源码留存参考，不参与应用链接。

## v0 方向与当前浇水操作

| 项目 | 约定 |
| --- | --- |
| 空间 | 花园永远在左、小屋在右，小屋左门连接花园 |
| 输入 | 左右短按切当前场景焦点；OK 互动；小屋长按左进入花园，花园长按右回屋 |
| 未定义输入 | OK 长按、双击、组合键没有额外功能；快速连续短按按独立点击处理 |
| 沫纯 | HOME_IDLE / HOME_SLEEP / OUT；出门后两处均没有人物 |
| 植物 | 橙色郁金香：种下、发芽、花苞、开放；成长值为 0–3 / 4–19 / 20–55 / 56 |
| 喝水 | 每次成功浇水记录一杯；按本地运行周期或可信 UTC+8 日期，每轮前四杯推进成长 |
| 浇水 | 当前增量：选择水壶按 OK 手动浇水，完成后原子保存杯数、每日额度和成长；OUT 不阻止魔法水壶工作 |
| 日夜 | 07:00–19:00 DAY，其余 NIGHT；室内暖灯、窗外暗；花园月光和小灯 |
| 自主外出 | 按天生成并保存计划，玩家不命令出门或召回；离开/返回有简短提示 |
| 待机 | 恢复此前场景；首次按键只唤醒，并吞掉该次按住和松开全过程 |
| 保存 | 版本化 NVS 保存成长、累计/今日杯数、额度、日期和运行计时检查点；出门计划根据记住的生活时间恢复；相机位置未保存 |

成长额度不跨日结转，不保存待兑换次数；成长不会减少。UTC+8 日期来自联网 SNTP 校时，不以开机时长冒充日期。睡觉时间与外出调度已按下文规则实现，验收待完成。

## Milestone A：本轮交付边界

已实现代码：开机进入小屋、独立透明 Q 版角色、OK 显示“主人回来啦～”、再次 OK 关闭；长按左键 700 ms 后，用 650 ms smoothstep 镜头经过门口进入花园；长按右返回；两场景各保留两个焦点。画面采用 528×320 连续世界，240×320 视口；花园视口 x=0，小屋视口 x=288，门口在中间。

Milestone A 原型使用独立绘制的卡通橙色郁金香和珊瑚红水壶标识交互位置，最初只显示说明；当前浇水增量见下文。HOME_SLEEP、OUT、日夜与四阶段已接入；生活节奏规则见下文。OUT 的渲染分支会隐藏角色。待机为 60 秒无操作关闭背光，场景保留在 RAM；不是低功耗深睡。杯数、成长、每日额度和日期已支持断电恢复，相机位置仅保留在 RAM；角色调度根据持久化生活时间恢复。

素材：原立绘衍生的 `mochun-idle-reference-v3.png`；连续白天背景 `world-day-master-v2.png`。视觉修订采用更圆润紧凑的约两头身比例、减弱卷发，将木地板延伸到脚下，并以小光斑替代选择方框。Q 版保留站姿，并新增夜间坐睡姿。屏幕边角有官方 30 px 圆角遮罩，重要文字向内避让。

## 模块职责

```text
官方 BSP：显示、唯一 ADC 所有者、LVGL 渲染任务
  ↓ calibrated millivolts（10 ms 采样）
main/main.c：硬件适配、主循环、背光、LVGL 锁
  ↓ raw key
main/passport/input.c：30 ms 防抖、700 ms 长按、单次事件、唤醒吞键
  ↓ semantic event
main/passport/world.c：焦点、对话、转场、待机、纯数据
  ↓ read-only world
main/passport/view.c：LVGL 物件、图层、脚下焦点提示、中文对话
```

状态机与输入不依赖 ESP-IDF/LVGL，可在主机编译测试。应用主循环是世界状态的唯一写入者；绘制访问均在 `bsp_lvgl_lock()` 内。存储和联网各使用独立后台任务，没有第二个 ADC1 实例。BSP 原有 button 任务保留初始化但不注册应用回调，应用复用校准电压读取接口，避免继承示例的 500 ms 长按与双击延迟。逻辑映射暂定 BSP UP→LEFT，DOWN→RIGHT，需真机确认按键位置。

转场开始清除对话，动画期间输入被消费，不在结束后补发；镜头完全到达才提交 scene。跨键的 ADC 跳变不能生成第二次手势；读取失败取消当前手势，等待稳定松开。毫秒计时使用无符号差值处理回绕。

## 渲染与内存

背景 RGB565：528×320×2 = 337,920 bytes；角色 RGB565A8：150×200×3 = 90,000 bytes；四阶段郁金香各为 RGB565A8：55×65×3 = 10,725 bytes；水壶 RGB565A8：60×45×3 = 8,100 bytes；加入夜景和睡姿后合计 906,840 bytes 只读 Flash 数据。RGB565A8 为 RGB 平面后接 alpha 平面。LVGL 使用官方局部 DMA 缓冲，不分配 528×320 世界帧缓冲，不依赖 PSRAM。转换脚本 `tools/prepare_passport_images.py` 可重现资源，依赖 Pillow。原素材与生成 C 均在 `assets/images/passport/`。

中文使用 SIL OFL 授权的 Noto Sans SC 字体子集，weight 500 / 18 px / 4 bpp / 不压缩，转换器 `lv_font_conv@1.5.3`。源字体、OFL 与生成 C 在 `assets/fonts/passport/`；UI 显式绑定该字体。字符集合必须覆盖所有标签与标点，新增文案必须重新转换和检查。完整源字体不链接到固件。

应在真机记录：开机/转场最低可用 heap、最大连续空闲块、Flash 大小、转场实际帧时长和中文清晰度。24 KB LVGL 池沿用基线，不能把未测量的帧率或内存余量当作保证。

## 后续实现顺序

1. 真机：启动、中文、按键映射、镜头方向、圆角与画面比例。同时验收当前手动浇水增量。
2. 当前数据验收：版本化 NVS 迁移、跨日、重启额度与时钟可信度。
3. 当前互动验收：每天杯数、四阶段、原子事务与魔法水壶动画。
4. C 生活：日夜素材、睡觉、每日持久化随机外出计划、离线跨时段恢复。
5. C 电源：低功耗策略与断电恢复；调试参数只通过开发构建开放。

未来持久化只在业务事件完成后提交，不随动画帧写 Flash。浇水应原子保存杯数、每日额度与成长，避免断电重复奖励。时间不可信时保留记录，不通过反复重启重置每日额度。

## 验证与真机验收

主机测试：`tests/test_passport.c` 覆盖防抖、长短互斥、OK 长按无动作、唤醒吞键、转场锁、ADC 异常、计时回绕、镜头单调/端点、场景焦点、待机恢复、OUT 对话。已接入官方 `tools/validate.sh --static`；完整检查为 `tools/validate.sh`，固件要求 ESP-IDF 5.5.3。

真机验收：

- 冷启动显示小屋、角色、默认沫纯焦点，无官方测试菜单。
- OK 文案完整“主人回来啦～”，没有缺字框；再次 OK 关闭。
- <700 ms 松开只切焦点；≥700 ms 左键触发一次转场，松开不再短按。
- 小屋向左经过门框进入花园，右键按相同逻辑回屋；连续 50 次无残影/重启。
- 动画中按键不排队；在花园待机后按 OK 只唤醒，再次 OK 才互动。
- 记录物理键位、实际效果与资源日志；电脑渲染或编译成功均不能替代此项。

当前检查结果另见交付记录。烧录应在生成并核验确切固件之后由用户授权；本轮不会因检测到 USB 就自动刷写。

## 重现电脑端渲染检查

准备 LVGL 9.5.0 源码与本机 C/C++ 编译器；此检查不涉及浏览器、服务端或手机应用。

```sh
cmake -S tests/passport_render -B build/host-render -DLVGL_SOURCE=/path/to/lvgl-9.5.0
cmake --build build/host-render -j8
cd build/host-render
./passport_render
```

检查使用 24 KB LVGL 内存池、240×20 RGB565 局部显示缓冲、真实应用 view 和已转换素材。验证字形描述符与缺字负例，输出 house/dialog/door/garden/garden-can/house-room/status/status-unavailable/status-sleep 九张 PPM 供检查。这证明电脑端可以渲染，不能代表实体屏颜色、速度或功耗；目标芯片仍需通过 ESP-IDF 固件检查。

## 状态页面

在小屋短按左右选中第二个焦点“状态”，按 OK 打开，再按 OK 关闭。原有长按左键也会关闭状态页并进入花园；待机会关闭页面，唤醒后恢复场景。页面显示电量百分比、开机运行小时/分钟，以及 HOME_IDLE / HOME_SLEEP / OUT 对应的当前状态。运行时间是本次开机经过的时长，不是日历时间；自主生活调度仍留待后续阶段。

独立应用任务初始化现有 BSP 电量计，每 10 秒读取一次，以原子变量发布电量；主循环仍是世界状态的唯一写入者。不可用时显示 --%，屏幕右上角同步显示电量，不虚构电量或充电状态。后台任务与应用同生命周期，运行中不删除页面。主机渲染覆盖正常/缺失电量与全部角色状态；真实电量读数仍需真机验收。


## 每日杯数、成长与 Wi-Fi

每次成功浇水记录一杯。每轮额度前四杯推进成长，更多杯数仍计入今日和累计记录。4 点幼苗、20 点花苞、56 点开花，从新种子开始需要十四轮完整成长额度。成长不减少，开花后保持盛开并继续记录喝水。花园顶部栏保留四滴 10×14 像素的小水滴，位置为 x=88／102／116／130、y=28，放在对象名称与 Wi-Fi 图标之间，不加底框；离开花园或转场时隐藏。植物详情使用各阶段简短描述，浇水完成只给一句轻轻的回应。花园不展示杯数、成长百分比、成长条和计时／刷新规则；后台记杯和四次成长额度仍保持。下一株与收藏系统尚未实现。

存储任务保存浇水开始时冻结的快照，跨午夜的操作属于开始日期；失败重试同一快照，不重播动画、不重复计数。提交成功后才由应用主循环更新世界状态。

无可信日期时也立即可浇水。每累计运行 86,400 秒刷新四次成长额度，背光待机也计时，关机时间不计入。超过四杯仍记杯，未用额度不结转。本地周期默默运行，花园不增加计时说明。首次可信校时将本轮杯数和已用额度接入过渡轮，下一向前的自然日才刷新；未知／回退日期恢复本地计时，不赠送额度。持续通电期间，已校准时钟断网仍正常运行。

当前 `cottage` / `watering` 记录为 40 bytes：0–3 为 `XYWC`，4 为版本 3，5–6 为成长／额度，7 为时钟模式，8–19 为小端 uint32 累计杯数／本轮杯数／最后 YYYYMMDD，20–27 为小端 uint64 累计运行秒数，28–31 为 uint32 本地周期进度，32–39 保留为零。模式为本地 0、自然日 1、过渡轮 2。`growth_record.c` 校验数据。版本 2 保留植物、杯数、日期和额度，计时检查点从零开始；版本 1 保留累计杯数，因缺少历史成长，新植物从零开始。下一杯或计时检查点提交迁移。缺失记录从零开始；不兼容数据／NVS 错误保留原数据并禁用浇水，不擦除。Wi-Fi 凭证使用独立 SDK 命名空间。旧固件不能读取版本 3，降级时不得重置记录。

世界状态累计单调运行时间，在未转场／动画／保存且距输入至少 200 ms 时，每 60 秒请求后台检查点，并在额度／日期模式边界提交。浇水事务同时携带计时检查点；成功确认只扣除冻结的时长，动画和重试期间的时间仍待保存。失败保留快照，按 OK 重试，待机／唤醒后仍保留，其他输入不能覆盖。纯计时提交不显示浇水完成，也不推迟待机。存储任务分别校验计时和记杯变更。突然断电会丢失上次成功检查点之后的计时，正常情况下少于一分钟加当前操作时长，长按或存储失败可扩大此窗口；不会重置已保存额度或重复已保存杯数。保守丢失只会延后下一轮，不会提前发放额度。


电量旁 Wi-Fi 图标获取 IP 后为绿色，未连接时为灰色。小屋状态页用左右选择返回、设置 Wi-Fi、清除 Wi-Fi，按 OK 执行。清除需要再次 OK 确认，左右取消；仅清除网络，不影响杯数和成长。原有长按转场仍可用。

设置 Wi-Fi 开启 WPA2 热点 `Xyloom-Setup`，每次生成八位密码并显示在屏幕上。手机连接热点，遇到无互联网提示仍保持连接，再打开 `http://192.168.4.1`。选择扫描到的 2.4 GHz 网络或输入名称，填写 8–63-byte 密码。ESP-IDF 在设备本地记住一个网络，重新配置替换旧网络。应用日志/源码不含凭证，不使用蓝牙或 BLUFI 小程序，手机页面采用独立简洁界面。

HTTP 任务扫描并接收凭证，独立联网任务负责连接，不访问 LVGL。获取 IP 后五秒或开始配网五分钟后关闭热点；密码错误或网络不可用时，可在网页修正或重新开启设置。重连前五次每十秒尝试，之后每六十秒尝试。SNTP 使用 `ntp.aliyun.com`，UTC+8 日期仅在本次启动获得合理校时结果后可信。校时后持续通电期间断网仍计时；重启只需为自然日重新校时，不影响互动。无可信日期时状态页显示“离线计时”。向前跨午夜和时钟模式变化通过同一原子检查点路径保存。

主机测试覆盖十四天最短周期、每日上限/更多杯数、闰年/月份/年份边界、阶段门槛、开花后记录、未知／回退时钟、24 小时边界、多轮计时、重启进度／额度、保守校时、版本 1／2 迁移、纯计时提交和事务重试和凭证表单解析。真机仍需验收热点发现、扫描/手动选网、错误密码、保存后重连、重新配网、清除凭证、SNTP、跨午夜、可读性和联网/UI 同时运行的内部内存余量。

配网入口同时识别 IPv4 和 IPv4 映射的 IPv6 热点地址，以兼容 ESP-IDF 的双栈 HTTP 监听，仍拒绝其他目标地址。界面先比较可见状态，再更新 LVGL；静止画面不持续重绘，浇水、转场、水滴、植物阶段和状态页运行时长仍会随显示内容变化而更新；后台杯数和同阶段成长变化不重绘静止花园。

## 模拟器联网

`CONFIG_COTTAGE_SIMULATOR_NETWORK` 默认关闭。可选的
`sdkconfig.simulator.defaults` 配置会自动连接开放的 `Emulator Host Bridge`
热点。模拟器通过本地服务器和电脑当前的网络转发请求，不需要家庭 Wi-Fi 密码。
Wi-Fi 配置只使用 RAM，不读取、替换或清除真机保存的凭据。浇水记录仍使用正常的
NVS 存储与时钟规则。
此配置把应用日志输出到浏览器运行时支持的 UART0，而不使用真机的
USB-Serial-JTAG 控制台。UART0 的真机引脚与本板背光冲突，因此模拟器配置
绝不能烧录到真机。

使用 `./tools/validate.sh --simulator` 构建此开发配置：运行主机检查，并用两份
defaults 执行固件验证，保留已验证归档，将镜像复制到
`build/Cottage-simulator-full.bin`，不替换普通版的
`build/FoloToy-AI-Passport-full.bin`。将模拟器镜像上传到本地模拟器，不要刷到真机。
普通版完整验证仍使用 `./tools/validate.sh`。

在 Cottage 状态页选中“清除 Wi-Fi”并按 OK 确认，即可断网，本次运行停止自动
重连。选中“设置 Wi-Fi”并按 OK，重新连接虚拟热点，不启动真机配网页。重启
模拟器版会重新联网。电脑外网中断时，Wi-Fi 仍可能已连接但 SNTP 失败，网络桥
指示灯不能证明日期可信。应同时检查 Cottage 状态页日期、UART 校时事件和
Wi-Fi 检查器的 DNS、UDP 流量。断网后已同步的时钟可以继续运行；验证从未校时
的离线冷启动，需要在启动前阻断网络桥。真实配网、无线信号和 BLE 仍需真机验证。

`tests/test_passport_network.c` 用模拟驱动与任务事件执行真实的模拟器配置网络
worker，覆盖 RAM 配置、首次连接、可信 SNTP、忘记后不重连、手动恢复、瞬时配置
失败重试和启动失败清理，并断言没有读取 Flash 凭据或调用恢复配置操作。

## 手动浇水基础（旧版记录格式）

以下保留旧版仅累计次数的增量记录，由上文每日成长格式和界面替代。

最初的浇水增量仅保存累计次数，当前行为和记录格式以下文为准。水壶用 450 ms 飞到花旁、900 ms 倾斜出水、450 ms 返回，动画总长 1,800 ms；沫纯为 OUT 时照常执行。动画与保存期间吞掉输入，按住的键必须松开后才能进行下一次操作，不排队、不重复计数，也不触发转场或待机。

动画完成后，存储任务保存目标次数；只有保存成功才更新世界中的次数并显示完成提示。保存失败保留此前次数，按 OK 重试保存同一个目标值，不再次播放动画或再次增加次数。重启只恢复已经保存的完成次数；中途断电可能保留旧值或已经提交的新值，不会保存半个记录。超过 uint32 上限时拒绝新增，避免回绕。

`main/passport/storage.c` 的独立任务独占 NVS，应用主循环通过队列发送快照、接收结果，并保持世界状态的唯一写入权。使用现有 NVS 分区、命名空间 `cottage`、键 `watering` 保存一个 12-byte blob：字节 0–3 为 `XYWC`，字节 4 为版本 1，字节 5–7 保留为零，字节 8–11 为小端 uint32 累计次数。`watering_record.c` 独立编解码。缺少记录时从零开始；NVS 初始化失败、格式或版本不兼容时显示存储不可用，保留原记录，不自动擦除或重置。存储任务启动失败也禁用浇水并显示错误。

本轮不实现可信日历、每天上限、喝水兑换、植物成长动画或场景恢复。四阶段枚举仍是后续接口，花朵仍使用现有固定插画，不将累计次数表述为已经落地的成长系统。

主机测试覆盖计时回绕、OUT 浇水、动画和保存锁、防重复计数、保存重试、计数上限、记录格式及实际 NVS 任务的故障注入。渲染检查额外输出飞行、出水、返回、保存中、保存失败、完成及计数画面，并核验全部中文字形。真机应检查：选水壶触发、选花查看、动画无裁切、长按不误触、完成后重启仍保留次数、断电后记录完整，以及原转场/待机正常。

转场期间确认稳定松开后，转场结束后的新按键立即重新生效；仍按住的键、无效 ADC 读数或尚未确认的松开继续被抑制。原始输入流程回归覆盖弹窗、往返镜头、浇水保存失败／重试和唤醒按键消耗。

## 本地生活节奏（2026-10-09）

`life.c` 提供独立可测试的日夜、睡眠和出门逻辑。UTC+8 的 07:00–18:59 为白天，19:00–06:59 为夜晚。沫纯在 22:00–06:59 休息，使用透明坐睡图片和安静的睡眠对话。每个本地日期安排一次 30 分钟散步，开始时间在 10:00–16:59，由纪元日确定，因此重启不会重新抽取当天计划。OUT 在两侧场景均隐藏角色，浇水及其原子保存仍可用。

网络仅在接受 SNTP 校时后发布可信 UTC 秒数。离线时主循环使用单调开机时间推进记住的生活时间。从未记住／校准时间的设备以白天 HOME_IDLE 启动，不猜测散步安排。独立的 16 字节带版本和校验记录 `cottage/life` 保存生活时间。存储线程每 15 分钟及日夜／睡眠／出门边界保存，失败重试至少间隔五秒。断电时间不计入；突然掉电可能令生活时间延后尚未保存的间隔。浇水 v3 记录、额度和校时规则保持原样。损坏或未知版本的生活记录会被保留，并停止生活时间写入；实时使用及浇水不受影响。

测试覆盖日夜／睡眠／出门边界、重启计划稳定、离线返回、记录损坏和实际存储线程失败。主机 LVGL 快照包括两种光照、睡姿／对话、OUT 以及出门期间浇水。真机时间、颜色及断电恢复仍待验收。

### 本地模拟器按键适配

本地模拟器的合成单击时序在安静场景中无法可靠匹配 Cottage 按松开判定的输入。未修改的归档固件使用明确 ADC 电平短按，已展示欢迎弹窗开关与焦点切换。`tools/cottage_simulator_input.patch` 提供模拟器侧适配：文件名包含 `Cottage` 时，每次合成短按转换为排队的 30 ms 现实时间按下，再留 30 ms 松开间隔；双击发送两个完整短按。长按仍使用真实按下／松开，其他固件名保留上游手势。在模拟器源码根目录运行 `git apply /absolute/path/to/tools/cottage_simulator_input.patch`；只修改 `public/app.js`，不改变固件或 BSP。本地镜像文件名保留 Cottage 以启用适配。现实时间节奏仅是本地开发辅助，不等于真机时间测量；当前镜像验收结果另见验证记录。

### 模拟器网络传输开关

`tools/cottage_simulator_offline.patch` 为本地模拟器增加仅用于测试的网络传输开关，在同一页面上传固件和硬重启后保留状态。从模拟器源码根目录在输入补丁之后应用。开关关闭主机网络桥并丢弃虚拟设备发出的帧；恢复时重连网络桥。不会更改电脑网络设置、凭据或固件时间。模拟器仍可能提供虚拟关联和 DHCP 地址，因此绿色 Wi-Fi 图标不代表互联网可用。通过未接受 SNTP 及状态页离线日期字段判断未校时。刷新页面会恢复在线。补丁只更改模拟器 JavaScript，不修改设备固件。
