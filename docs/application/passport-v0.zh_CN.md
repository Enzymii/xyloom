# AI Passport Prototype v0：开发与架构

## 目标与范围

让沫纯住进一台离线 AI Passport。先完成 Milestone A 的工程与画面，再在真机验收角色大小、中文、按键手感和连续空间转场。手机 Web、后端、BLE 同步、AI 对话、旅行照片、网络配置均不在本轮范围。

官方上游：https://github.com/FoloToy/ai-passport 。基线提交 `0b9e4c81ee4421c0bac39ca3561d65a8285acd4a`。保留 BSP 与分区表，应用启动不再进入硬件测试菜单。官方示例源码留存参考，不参与应用链接。

## 已冻结的完整 v0 规则

| 项目 | 约定 |
| --- | --- |
| 空间 | 花园永远在左、小屋在右，小屋左门连接花园 |
| 输入 | 左右短按切当前场景焦点；OK 互动；小屋长按左进入花园，花园长按右回屋 |
| 未定义输入 | OK 长按、双击、组合键没有额外功能；快速连续短按按独立点击处理 |
| 沫纯 | HOME_IDLE / HOME_SLEEP / OUT；出门后两处均没有人物 |
| 植物 | 橙色郁金香：种下、发芽、花苞、开放；成长值暂定 0–1 / 2–4 / 5–8 / 9+ |
| 喝水 | 选择水壶 OK 记录，每个本地日最多 4 杯，每杯增加一次浇水机会 |
| 浇水 | 选择花 OK 消耗机会，完成动画后增长；OUT 不阻止魔法水壶工作 |
| 日夜 | 07:00–19:00 DAY，其余 NIGHT；室内暖灯、窗外暗；花园月光和小灯 |
| 自主外出 | 按天生成并保存计划，玩家不命令出门或召回；离开/返回有简短提示 |
| 待机 | 恢复此前场景；首次按键只唤醒，并吞掉该次按住和松开全过程 |
| 保存 | 后续使用版本化 NVS 保存成长、杯数、次数、日期、出门计划、最后场景 |

尚未冻结的策略：未用浇水次数是否跨日累计（建议上限 4，禁止静默丢失）、无可信本地时间时如何设置时钟、夜间睡觉时间、外出概率与时长。Milestone A 不伪造墙上时钟，也不以开机时长冒充日期。

## Milestone A：本轮交付边界

已实现代码：开机进入小屋、独立透明 Q 版角色、OK 显示“主人回来啦～”、再次 OK 关闭；长按左键 700 ms 后，用 650 ms smoothstep 镜头经过门口进入花园；长按右返回；两场景各保留两个焦点。画面采用 528×320 连续世界，240×320 视口；花园视口 x=0，小屋视口 x=288，门口在中间。

A 的花园使用独立绘制的卡通橙色郁金香和珊瑚红水壶标识交互位置，OK 显示说明，不增加喝水与成长。HOME_SLEEP、OUT、日夜与四阶段已经有领域类型，但自动调度、夜景、睡姿尚未接入。OUT 的渲染分支会隐藏角色。待机为 60 秒无操作关闭背光，场景保留在 RAM；不是低功耗深睡，也不承诺断电恢复。

素材：原立绘衍生的 `mochun-idle-reference-v3.png`；连续白天背景 `world-day-master-v2.png`。视觉修订采用更圆润紧凑的约两头身比例、减弱卷发，将木地板延伸到脚下，并以小光斑替代选择方框。Q 版目前是站姿，坐姿/睡姿之后补充。屏幕边角有官方 30 px 圆角遮罩，重要文字向内避让。

## 模块职责

```text
官方 BSP：显示、唯一 ADC 所有者、LVGL 渲染任务
  ↓ calibrated millivolts（10 ms 采样）
main/main.c：硬件适配、主循环、背光、LVGL 锁
  ↓ raw key
main/passport/input.c：30 ms 防抖、700 ms 长按、单次事件、唤醒吞键
  ↓ semantic event
main/passport/world.c：焦点、对话、转场、待机、纯数据
  ↓ read-only world
main/passport/view.c：LVGL 物件、图层、脚下焦点提示、中文对话
```

状态机与输入不依赖 ESP-IDF/LVGL，可在主机编译测试。应用主循环是世界状态的唯一写入者；绘制访问均在 `bsp_lvgl_lock()` 内。没有新增后台网络任务、没有第二个 ADC1 实例。BSP 原有 button 任务保留初始化但不注册应用回调，应用复用校准电压读取接口，避免继承示例的 500 ms 长按与双击延迟。逻辑映射暂定 BSP UP→LEFT，DOWN→RIGHT，需真机确认按键位置。

转场开始清除对话，动画期间输入被消费，不在结束后补发；镜头完全到达才提交 scene。跨键的 ADC 跳变不能生成第二次手势；读取失败取消当前手势，等待稳定松开。毫秒计时使用无符号差值处理回绕。

## 渲染与内存

背景 RGB565：528×320×2 = 337,920 bytes；角色 RGB565A8：150×200×3 = 90,000 bytes；郁金香 RGB565A8：55×65×3 = 10,725 bytes；水壶 RGB565A8：60×45×3 = 8,100 bytes；合计 446,745 bytes 只读 Flash 数据。RGB565A8 为 RGB 平面后接 alpha 平面。LVGL 使用官方局部 DMA 缓冲，不分配 528×320 世界帧缓冲，不依赖 PSRAM。转换脚本 `tools/prepare_passport_images.py` 可重现资源，依赖 Pillow。原素材与生成 C 均在 `assets/images/passport/`。

中文使用 SIL OFL 授权的 Noto Sans SC 字体子集，weight 500 / 18 px / 4 bpp / 不压缩，转换器 `lv_font_conv@1.5.3`。源字体、OFL 与生成 C 在 `assets/fonts/passport/`；UI 显式绑定该字体。字符集合必须覆盖所有标签与标点，新增文案必须重新转换和检查。完整源字体不链接到固件。

应在真机记录：开机/转场最低可用 heap、最大连续空闲块、Flash 大小、转场实际帧时长和中文清晰度。24 KB LVGL 池沿用基线，不能把未测量的帧率或内存余量当作保证。

## 后续实现顺序

1. A 真机：启动、中文、按键映射、镜头方向、圆角与画面比例。A 未验收前不扩张玩法。
2. B 数据：版本化 NVS；不自动擦除不兼容 NVS；跨日与时钟可信度策略。
3. B 互动：每天杯数、浇水次数、四阶段、可重复验证的事务与魔法水壶动画。
4. C 生活：日夜素材、睡觉、每日持久化随机外出计划、离线跨时段恢复。
5. C 电源：低功耗策略与断电恢复；调试参数只通过开发构建开放。

未来持久化只在业务事件完成后提交，不随动画帧写 Flash。浇水应原子保存“扣次数+加成长”，避免断电重复奖励。时间不可信时保留记录，不通过反复重启重置每日额度。

## 验证与真机验收

主机测试：`tests/test_passport.c` 覆盖防抖、长短互斥、OK 长按无动作、唤醒吞键、转场锁、ADC 异常、计时回绕、镜头单调/端点、场景焦点、待机恢复、OUT 对话。已接入官方 `tools/validate.sh --static`；完整检查为 `tools/validate.sh`，固件要求 ESP-IDF 5.5.3。

真机验收：

- 冷启动显示小屋、角色、默认沫纯焦点，无官方测试菜单。
- OK 文案完整“主人回来啦～”，没有缺字框；再次 OK 关闭。
- <700 ms 松开只切焦点；≥700 ms 左键触发一次转场，松开不再短按。
- 小屋向左经过门框进入花园，右键按相同逻辑回屋；连续 50 次无残影/重启。
- 动画中按键不排队；在花园待机后按 OK 只唤醒，再次 OK 才互动。
- 记录物理键位、实际效果与资源日志；电脑渲染或编译成功均不能替代此项。

当前检查结果另见交付记录。烧录应在生成并核验确切固件之后由用户授权；本轮不会因检测到 USB 就自动刷写。

## 重现电脑端渲染检查

准备 LVGL 9.5.0 源码与本机 C/C++ 编译器；此检查不涉及浏览器、服务端或手机应用。

```sh
cmake -S tests/passport_render -B build/host-render -DLVGL_SOURCE=/path/to/lvgl-9.5.0
cmake --build build/host-render -j8
cd build/host-render
./passport_render
```

检查使用 24 KB LVGL 内存池、240×20 RGB565 局部显示缓冲、真实应用 view 和已转换素材。验证字形描述符与缺字负例，输出 house/dialog/door/garden/garden-can/house-room/status/status-unavailable/status-sleep 九张 PPM 供检查。这证明电脑端可以渲染，不能代表实体屏颜色、速度或功耗；目标芯片仍需通过 ESP-IDF 固件检查。

## 状态页面

在小屋短按左右选中第二个焦点“状态”，按 OK 打开，再按 OK 关闭。原有长按左键也会关闭状态页并进入花园；待机会关闭页面，唤醒后恢复场景。页面显示电量百分比、开机运行小时/分钟，以及 HOME_IDLE / HOME_SLEEP / OUT 对应的当前状态。运行时间是本次开机经过的时长，不是日历时间；自主生活调度仍留待后续阶段。

独立应用任务初始化现有 BSP 电量计，每 10 秒读取一次，以原子变量发布电量；主循环仍是世界状态的唯一写入者。不可用时显示 --%，屏幕右上角同步显示电量，不虚构电量或充电状态。后台任务与应用同生命周期，运行中不删除页面。主机渲染覆盖正常/缺失电量与全部角色状态；真实电量读数仍需真机验收。
